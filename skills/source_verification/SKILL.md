# 官方来源、链接与重复转载核验

## 核验目标

本技能的每一项核验结果都必须同时给出发布单位或网站全称、文章来源/页面完整标题和指向具体原文的链接。首页、栏目页、域名、搜索结果页或只有单位名称的引用都不能作为完整文章来源；无法确认时必须明确标记“来源：未提供/待核验”。

对用户提交的每个文件、链接或记录回答五件事：

1. 它是否能追溯到发布机构自己的官方原始页面或官方文件？
2. 发布机构是谁，发布日期/更新时间是什么，证据在哪里？
3. 链接当前是否有效，是否发生跳转、失效、登录墙、反爬或指向附件？
4. 它与其他记录是否是完全重复、同文转载、改标题转载、摘要转载或仅主题相似？
5. 如果不是原始来源，最可能的原始来源是什么，判断依据和不确定性是什么？

## 来源判定规则

### 证据优先级

按强到弱建立来源证据：

1. 发布机构官网的文章详情页或官方数据发布页，页面同时显示标题、机构和日期。
2. 发布机构官网直接提供的 PDF/Word/Excel 等文件，并能由官方栏目或详情页链接到它。
3. 国家、省、市政府门户的转载页，页面明确标注“转载自/来源于”并保留原始链接或完整发布信息。
4. 官方政务新媒体、官方公报或正式数据库，但要记录账号/数据库身份和可核查页面。
5. 新闻媒体、商业数据库、搜索摘要、个人博客、论坛和二次整理，只能作为线索，不能单独认定原始官方来源。

域名包含 `gov.cn`、`统计局` 或机构名称只是线索，不是充分证据。还要检查页面署名、栏目归属、页脚/联系方式、原始链接、标题和内容的一致性。对于短链、聚合页和下载链接，继续追到最终落地页。

## 工作流程

### 1. 建立清单和指纹

- 为每个输入生成稳定 ID，记录原始文件名/原始 URL，不覆盖原始记录。
- 文件：记录扩展名、大小、页数/工作表、创建/修改时间（仅作辅助证据），并提取标题、作者/机构、发布日期、正文、页眉页脚、链接和文档属性。
- 网页：保存规范化 URL、最终 URL、页面标题、可见机构、日期、正文摘要和抓取时间。
- 生成规范化标题（去空白、标点、常见栏目后缀）和正文指纹。不要把标题相同但正文不同的文件直接判定为重复。

### 2. 查找官方原始出处

- 用完整标题、标题核心短语、机构名、日期和关键句分别检索。
- 优先在候选机构的官网域名和官方栏目内检索，再扩大到政府门户和可信转载。
- 比较候选页面的标题、发布日期、机构、正文段落、附件名称和发布时间；至少保留一个能复核的原始页面链接。
- 如果只有转载页，沿着“来源/原文/责任编辑/文章来源”字段、页面内链接和相同正文继续回溯。
- 对搜索结果摘要、缓存页面或无法打开的页面，只作为线索；除非有第二个独立证据，不得写成已确认。

### 3. 核验机构和发布日期

分别填写“页面显示值”和“核验结论”，不要把文件系统修改时间当成发布日期：

- **机构：** 页面署名、栏目、页脚、发布单位字段、文号或官方账号是否一致；记录机构全称和层级。
- **发布日期：** 区分发布时间、发布日期、更新时间、转载时间、文件落款日期和统计期；如果页面只有“来源日期”，标明字段名称。
- **冲突：** 若附件封面、详情页和转载页日期不同，保留全部日期并解释可能的发布/转载关系，不要擅自选一个。
- **缺失：** 没有可核验日期时填“未找到”，不要根据 URL、文件名或抓取时间推断。

### 4. 检查链接有效性

对每个 URL 记录以下结果：

- 原始 URL、最终 URL、检查时间、HTTP 状态或浏览器结果。
- `2xx` 通常表示可访问；`3xx` 要记录最终落地 URL；`401/403`、验证码、登录墙、robots 或超时应标为“访问受限/无法确认”，不能直接判定内容不存在。
- `404/410`、明确的“页面不存在”或域名失效可标为“失效”；服务器错误、网络故障和临时限流标为“暂时不可用”。
- 检查最终页面是否仍是目标标题/机构/日期，避免把统一错误页、首页或下载空壳当成有效来源。
- HTTP 与 HTTPS、尾部斜杠、跟踪参数和短链可做规范化比较，但保留原始链接。

### 5. 识别重复、转载和近似内容

先做机械匹配，再做语义判断：

- **完全重复：** 文件哈希相同，或规范化正文完全相同。
- **同文转载：** 标题/正文高度一致，但发布机构、栏目或 URL 不同；保留最早且最接近原始发布的候选。
- **改标题转载：** 核心正文、段落顺序、数据和发布时间高度一致，标题有删改或加前缀。
- **摘要/节选转载：** 只有部分正文或摘要一致，不能把转载页当作完整原文。
- **疑似重复：** 标题相似或主题相同，但证据不足；标记需人工复核，不能合并。
- **非重复：** 只有相同主题、同一统计期或同一事件，但正文和发布事实不同。

比较时至少使用标题相似度、正文前后段、数字/专名、附件哈希、发布日期差异和来源链。转载关系应输出“转载页 → 原始候选”的证据，而不是只给一个相似度分数。

## 输出格式

默认输出以下表格，并在表后给汇总：

```markdown
# 文件与来源核验报告
## 一、结论摘要
## 二、逐项核验结果
| ID | 文件/标题 | 官方来源结论 | 机构 | 页面发布日期 | 链接状态 | 原始来源 URL | 重复/转载关系 | 证据等级 | 备注 |
## 三、重复与转载关系
| 记录 A | 记录 B | 关系 | 共同证据 | 原始来源候选 |
## 四、待人工复核项
## 五、证据与访问记录
```

官方来源结论只使用：`已确认官方原始来源`、`官方转载`、`疑似官方但证据不足`、`非官方/二次来源`、`未找到原始来源`。链接状态只使用：`有效`、`重定向后有效`、`失效`、`访问受限`、`暂时不可用`、`未检查`。

每项必须同时给出：原始输入、核验过的标题、机构、日期、最终 URL、检查时间和可复核证据。每个链接旁都给出完整 Markdown 超链接；不能只写域名或网站名称。对用户附件标注文件路径和页码/工作表/行号，便于回查。

## 质量和安全边界

- 不因文件名、作者自称、搜索排名、`gov.cn` 域名或 HTTP 200 单独认定官方来源。
- 不把访问受限、反爬、临时 5xx 或缺少日期的页面误报为失效或已核验。
- 不删除、覆盖或改写用户提交文件；重复项只在报告中标记，并保留原始记录。
- 不把同一事件的不同版本自动合并；涉及修订、勘误、季度更新或重新发布时，作为不同版本记录。
- 只引用实际核验过的页面和文件；找不到证据时明确说“无法确认”，不补写机构、日期或链接。
