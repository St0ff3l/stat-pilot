# 价格指数对 GDP 各项影响分析

## 适用范围

本技能用于把价格指数、GDP 及其分项放在同一个统计口径下分析。它支持年度、季度、月度和指定时间窗口。若用户提交了文件，先把文件视为待核验的输入数据；不要因为文件名、表头或制表单位看起来权威，就直接把它当作官方数据。

## 地区默认规则：优先深圳市

除非用户在问题、附件或数据表中明确写出其他城市/地区，否则统一将 `region` 设为“深圳市”，先回答深圳本地的价格指数与 GDP 分项关系：

1. 优先查找深圳市统计局官网、深圳市政府网站和深圳市官方统计数据平台发布的原始数据、统计公报、统计年鉴、统计月报和经济运行材料。
2. 国家统计局、国家数据平台和广东省统计局的数据主要用于指标定义、口径校验、趋势对照或深圳数据缺口补充；不能因为全国或广东数据更容易找到，就替代深圳主分析结果。
3. 报告标题、数据表和结论中明确写“深圳市”；涉及全国、广东省或其他城市时单列地区字段和对照说明，不得混在深圳数据中计算。
4. 如果用户明确指定“广州”“全国”“广东”或其他地区，尊重用户指定，并在输出开头说明已切换分析地区。
5. 如果附件中的地区标注与用户文字冲突，先指出冲突并按用户最新明确指令处理；无法判断时保留待核字段，不擅自把其他地区改写成深圳。

## 核心原则

1. **先统一口径，再讨论影响。** 明确地区、时间频率、基期、现价/不变价、同比/环比、累计值/当期值、季调口径、行业分类和 GDP 核算方法。不同口径不能直接相减、相乘或拼接。
2. **区分统计关系和因果关系。** 价格指数通常通过平减、实际购买力、利润率、需求、库存、贸易条件和政策预期影响 GDP。除非有识别设计、足够长的时间序列或权威研究支持，否则只能写“相关、传导渠道、可能影响”，不能写成确定的因果结论。
3. **优先使用原始官方数据。** 中国宏观统计优先核对国家统计局、国家数据平台、人民银行、海关总署以及对应省市统计局或政府部门的原始发布页；引用每个数字时给出发布机构、页面/表格标题、发布日期或统计期、完整链接。
4. **价格变动不等于产量变动。** 名义 GDP 可能因价格上涨而增加，而实际 GDP 增速可能下降。报告必须同时展示名义值、价格指标和实际量/不变价指标（如果可获得）。
5. **尊重 GDP 核算边界。** CPI 不是 GDP 平减指数，进口价格不直接进入国内增加值，PPI 也不能机械地代表全部 GDP 价格。说明每个指数覆盖的篮子、权重和与 GDP 分项的对应关系。

## 工作流程

### 1. 读取和盘点输入

- 列出每个附件的文件名、格式、覆盖期间、地区、表名、单位和可能的来源。
- 从 Excel/CSV/PDF/Word/HTML 中提取表头、脚注、基期、修订标记和数据值；保留原始行列含义，不要擅自把“累计增长”当作“当期增长”。
- 如果缺少关键数据，明确列出缺口，并通过官方公开来源检索补齐；检索不到时不要编造数据。

### 2. 建立指标映射

至少按下列层次映射，能拿到多少就分析多少：

| 层次 | 重点指标 | 典型价格传导 |
| --- | --- | --- |
| 支出法 GDP | 最终消费、政府消费、资本形成、固定资本形成、存货变动、货物和服务净出口 | 实际购买力、投资成本、库存重估、出口竞争力和贸易条件 |
| 生产法 GDP | 农林牧渔业、工业、建筑业、批发零售、交通仓储、住宿餐饮、金融、房地产、信息服务等增加值 | 上游成本、产品售价、利润率、产能利用率和行业间价格传导 |
| 收入/分配视角 | 劳动者报酬、营业盈余、生产税净额（如有） | 实际工资、利润挤压、税收和收入再分配 |
| 宏观价格指标 | CPI、核心 CPI、PPI、购进价格、GDP 平减指数、进出口价格指数、房地产价格等 | 消费端、生产端、国内产出价格和外贸价格的差异 |

### 3. 做可复核的定量分析

根据数据可得性选择方法，并标注方法名称和限制：

- **名义/实际拆分：** 对能够匹配的分项使用 `名义值 ≈ 价格指数 × 实际量`，或 `实际量/不变价值 ≈ 名义值 ÷ 对应平减指数`。注意指数基期和缩放系数，不能直接把同比百分比相除当成严格分解。
- **增长贡献：** 使用官方贡献率、拉动点数或按当期价格权重计算近似贡献；说明权重来源和链式加权误差。若只有总量同比，不能反推出各分项贡献。
- **相关性和滞后：** 在同一频率、同一时间窗口、同一口径下比较同比/环比，必要时检验 0–4 期滞后；样本太短时只做描述统计，不做显著性结论。
- **情景分析：** 设定“价格上涨/下跌、需求不变/收缩、成本能否传导”三类情景，给出 GDP 分项的方向、时滞和置信度，而不是只给一个点估计。
- **敏感性检查：** 更换基期、剔除异常月份、区分总指数与核心指数、比较名义和实际结果，说明结论是否稳定。

### 4. 解释传导链条

对每个 GDP 分项回答四个问题：

1. 该价格指数覆盖的商品/服务是否直接进入该分项？
2. 价格变化影响的是名义金额、实际数量、利润率，还是收入分配？
3. 影响是否可能通过工资、利率、财政政策、库存或贸易汇率二次传导？
4. 传导方向、时间滞后、可逆性和证据强度是什么？

特别注意：

- CPI 上升可能抬高消费名义金额，也可能压低实际消费；两者方向不必相同。
- PPI 上升可能抬高工业名义产值，也可能压缩下游利润和实际需求；要区分上游供给冲击与需求回暖。
- 进口价格上涨会影响成本和净出口，但进口本身从 GDP 支出法中扣除，不能把进口价格上涨直接当作国内 GDP 增加。
- 房地产价格、土地价格和资产价格可能影响投资、财富效应与金融条件，但不能直接等同于房地产增加值。
- 基数效应、季节性、政策调整和统计修订必须单列，避免把短期同比波动解释成结构性趋势。

## 输出格式

### 强制来源要求

本技能输出的每个事实、数字、图表、表格和分析结论都必须同时写发布单位或网站全称、文章来源/页面完整标题和指向具体原文的链接。只写单位、网站名、域名或栏目页均不合格；无法核验时写“来源：未提供/待核验”，不得编造 URL、标题、单位或数据。

### HTML 交互报表自动生成规则（核心交付物）

当用户指定了视觉风格（如“极客卡片”、“政务经典”、“现代板岩”、“暗黑海洋”、“瑞士编辑”）、传入了 `template_style`、或要求生成 HTML/速查卡/报告时，**必须直接生成独立的 HTML 报表文件**：

1. **读取内置模版**：直接读取本 Skill 目录下的 `./templates/template_<style>.html`（支持 `geek_weekly`、`authority_classic`、`slate_tech`、`dark_ocean`、`swiss_editorial`；未指定时默认使用 `geek_weekly` 极客卡片风）。
2. **填充核心组件**：
   - 顶部 Hero：报表大标题、地区名称、数据窗口、证据分级标签；
   - 顶部 5 个 KPI 芯片：名义与实际 GDP、隐含平减指数、CPI、PPI 及涨跌幅对比；
   - 吸顶章节导航条：包含 01 结论、02 口径、03 映射表、04 定量拆分、05 情景推演、06 局限待补、07 数据来源等锚点；
   - 价格指数 ↔ GDP 分项映射大表与结论表：包含分项名称、对应指数、名义影响、实际量影响、传导渠道、时滞与证据等级；
   - 规范来源清单（S1～Sn）：逐条提供发布机构全称、文章完整标题与具体原文超链接。
3. **输出规范与路径**：
   - 统一写入工作区 `output/` 目录（例如 `output/价格指数×深圳GDP影响速查卡.html`），不得直接写入工作区根目录。
   - 对话中输出关键结论摘要，并在末尾给出可直接在本地浏览器中打开的 Markdown 链接：`[打开输出目录](file:///.../output/)`。

### HTML 排版安全与无重叠硬性规范（防遮挡红线）

为彻底避免排版崩溃，生成或调整 HTML 时必须严格遵守以下准则：
1. **【严禁项】禁止在滚动容器内对表头添加 sticky 偏移**：如果表格外层包裹了 `.tbl-wrap { overflow-x: auto; }`，**绝对严禁**在 `thead th` 或 `thead` 上设置 `position: sticky; top: 44px;`！这会导致浏览器将其按滚动容器内部偏移计算，直接遮盖第一行内容。表头必须采用常规流（`position: static`）排版，保证表格第一行内容完全露出。
2. **【必选设置】吸顶导航锚点安全留白**：带有吸顶导航（`position: sticky; top: 0`）时，所有章节（`<section>` 或带有 `id` 的锚点目标）**必须强制设置 `scroll-margin-top: 64px`**，确保页面滚动定位到指定章节时，标题不会被吸顶导航栏遮盖。
3. **【标准安全 CSS 片段（请直接复用，切勿随意修改）】**：

/* 必须包含的安全滚动间距，防止吸顶导航遮挡章节标题 */

/* 必须包含的安全表格，严禁添加 position: sticky; top: ... 避免遮盖第 1 行内容 */

## 质量检查清单

- 是否区分 CPI/PPI/GDP 平减指数及其覆盖范围？
- 是否同时讨论 GDP 总量和可获得的各分项，而不是只说“对 GDP 有影响”？
- 是否把名义变化、实际变化和因果判断分开？
- 是否对基期、频率、地区、单位、修订和季节性做了核验？
- 是否避免使用未经核验的转载数字，并为每条数据提供官方来源、标题、日期和链接？
- 是否明确缺失数据、近似算法和结论置信度？
