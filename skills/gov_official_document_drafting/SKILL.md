# 政务公文起草（深圳统计官方风格）

## 技能定位

本技能用于起草政务公文和政务参阅材料。它参考深圳市统计局官方网站公开信息的组织方式和信息公开字段，不冒充深圳市统计局发文，不代替正式审核、签发、用印或发布。所有正式机构名称、文号、日期、统计数据和政策结论都必须以用户提供或可核验的官方材料为依据。

官方风格参考页见 `references/shenzhen_stats_official_style.md`。优先观察官方网站的“政务公开 > 政府信息公开目录”层级、文章标题、文章来源、发布时间、正文分段和页面底部主办单位，不复制原文内容，不虚构公文文号。

## 先选样式，再起草

如果用户没有明确指定文种，先根据任务目标选择一个样式，并在输出开头说明“已选择样式：……”。信息不足时使用方括号保留待补字段，例如 `[待补：主送机关]`、`[待补：文号]`、`[待补：联系人及电话]`，不要用猜测填充。

### 1. 通知公告（`notice`）

适用于部署工作、发布安排、提示事项和业务通知。结构建议为：

1. 标题（通常为“关于……的通知”）；
2. 主送机关；
3. 工作背景和目的；
4. 具体事项，使用“一、二、三……”分层；
5. 时间、范围、材料、联系人和联系方式；
6. 结语、发文单位、日期和附件。

### 2. 请示/报告（`request_report`）

请示突出“请示事项”和需要上级决策的内容，报告突出工作进展、成效、问题和下一步安排。结构建议为：依据与背景、基本情况、主要问题、拟采取措施或请求事项、附件、落款。请示不得把尚未获批的事项写成已决定事项。

### 3. 工作方案（`work_plan`）

适用于专项工作、统计调查、信息化建设和阶段性行动。结构建议为：总体要求、工作原则、工作目标、重点任务、实施步骤、责任分工、时间安排、保障措施、附件。任务应尽量写清责任单位、完成时限、交付物和验收口径。

### 4. 汇报材料/讲话稿（`briefing`）

适用于会议汇报、工作交流、领导讲话和阶段性总结。结构建议为：开场与主题、工作进展和成效、经验做法、存在问题、下一步工作、需要协调支持的事项。保持书面正式但便于口头表达，避免堆砌口号。

### 5. 政策解读/信息简报（`policy_brief`）

适用于政策发布后的解读、统计信息简报和领导参阅材料。结构建议为：政策或事项概览、出台背景、核心内容、影响分析、执行要点、常见问题、来源与发布日期。不得把推测性判断写成政策原文。

## 官方文风与排版约束

- 使用准确、克制、平实的政务表达；先事实和依据，再判断和建议。
- 标题、主送机关、正文层级、附件、落款和日期分明；段落短而完整，一级标题用“一、”，二级标题用“（一）”，事项编号用“1.”或“（1）”。
- 不擅自添加深圳市统计局印章、红头、正式文号、签发人、领导姓名或“已发布”等表述。需要这些字段时使用 `[待补：……]`。
- 引用官方政策、统计数据或公开文章时，保留发布单位、完整标题、发布时间/发布日期和具体原文链接；无法核验时明确写“来源：未提供/待核验”。
- 输出 HTML 时使用简洁的政务参阅样式：白底、深蓝标题、低饱和朱红作为强调色，保留来源区块和打印友好布局；不要把视觉装饰写成官方标识。

## 强制来源要求（不得省略）

本技能的来源要求是强制要求，并且与全局来源规则一致。凡是正文中的事实、数据、政策依据、机构动作、日期、结论或引用，都必须同时写明：

1. 发布单位或网站全称；
2. 文章来源/页面的完整标题；
3. 指向具体文章或页面的原文链接。

统一格式：`来源：[发布单位或网站全称：《文章来源/页面完整标题》](https://具体原文链接)`。只写单位、网站名、域名、栏目页、搜索结果页或“据官网”均不合格。每一条来源都必须链接到具体原文页面；同一段涉及多篇材料时逐项列出。用户提交的文件没有可验证网页链接时写“来源：用户提交文件（具体原文链接：未提供/待核验）”，不得自行补链。

## 交付格式

默认交付一份可直接审阅的 Markdown 公文草案，并在文末附“待核字段”和“来源清单”。如果用户要求 HTML，则同时生成打印友好的 HTML 文件，保存到工作区 `output/` 下的任务子目录，并在回复中列出文件名。输出前检查：文种是否匹配、标题是否准确、每个事实是否有来源、链接是否具体、是否误写正式文号或已发布状态。
